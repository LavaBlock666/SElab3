# 实验三 AI 辅助记录（开发过程素材）

> 说明：本文件是开发过程的事实记录，供撰写实验报告时引用；不是实验报告本身。

## 记录 1：领域模型与服务骨架

- 场景：把实验二的类图落成 C++ 代码，先要定实体、枚举和状态机。
- 提示要点：给出类图中的 6 个实体、3 个状态枚举，要求 C++17、不引入第三方库、状态转换集中校验。
- 生成结果：`model.h/model.cpp` 的实体与 `CanTransition()`，基本可用；但漏了 `Timestamp Now()` 的声明，编译报错。
- 人工修改：补声明；把金额从 `double` 改成 `int64_t` 分，避免浮点误差；补 UTF-8 字段转义函数（文件存储用 0x1f 分隔）。

## 记录 2：仓储与文件持久化

- 场景：课程环境没有数据库，需要把仓储接口落到文件。
- 提示要点：为 7 个仓储接口写文件实现，字段含换行也不能破坏格式。
- 生成结果：每个仓储各写一套 load/save，约 600 行，重复度高。
- 人工修改：抽出 `Table<T>` 模板统一 load/save/serialize，仓储只保留查询逻辑，代码量减少约 200 行。

## 记录 3：预约并发与幂等

- 场景：实验一要求“同一商品只能一条有效预约、重复请求返回原结果”。
- 提示要点：给出服务层伪代码，要求 C++ 实现并说明并发安全。
- 生成结果：只做了“先查后插”，没有锁，也没有幂等号；并发测试会出现两条有效预约。
- 人工修改：加 `std::mutex` 串行化“校验 + 写入”，预约增加 `request_id` 幂等号，仓储层再查一次有效预约；
  补 8 线程并发测试，断言成功 1 次、冲突 7 次。

## 记录 4：单元测试与缺陷修复

- 场景：为 7 个服务写单元测试。
- 提示要点：覆盖状态机、权限、锁定、唯一预约、举报联动、统计口径、持久化。
- 生成结果：16 组用例、96 个断言；其中“中文标题长度校验”用例失败——代码用 `std::string::size()` 按字节计数，
  一个汉字算 3 个字节，1 个汉字的标题通过了“至少 2 个字符”的校验。
- 人工修改：新增 `Utf8Length()` 按 UTF-8 码点计数，替换所有文本长度校验（提交 312ce89）。
  同时修正卖家统计口径：已确认商品应计入“预约中”而不是“在售”。

## 记录 5：命令行界面

- 场景：需要一个能完整演示的运行入口。
- 提示要点：四类角色的菜单、输入校验、异常提示，不能因为一次误操作退出程序。
- 生成结果：菜单与流程可用，但详情页最初只有“预约”，没有举报入口。
- 人工修改：详情页改成“预约 / 举报”二选一，举报原因用编号选择；所有操作包在 `Guard()` 里捕获 `DomainError`。

## 记录 6：图形界面（Web）

- 场景：任务要求图形界面；实验二的设计稿本身就是网页，因此最终选择“C++ 内置 HTTP 服务 + HTML 前端”。
- 提示要点：给出 8 个页面结构与配色、需要的操作，要求后端提供 JSON 接口、前端不引框架。
- 生成结果：先尝试了 ImGui 桌面版，中文字体与卡片布局成本高、和设计稿差距大；改为 HTTP 方案后，
  服务端一次生成 20 余个接口，前端一次生成 8 个页面。
- 人工修改：把服务端路由按“查询/操作”分组，统一 JSON 信封与错误码；前端补空状态、分页、
  二次确认弹窗；用命令行逐个接口验证（登录 Cookie、预约、审核、举报、统计），并修正了
  `Report` 处理函数与类型重名、`begin/end` 不匹配等问题。

## 记录 7：界面缺陷修复与并发改造（提交 67461e6）

- 场景：试用 Web 界面后发现三个问题——登录页与首页同时出现、通知红点常亮、预约后找不到确认完成入口。
- 生成结果：AI 第一版没有意识到 `[hidden]` 会被组件的 `display:flex/grid` 覆盖。
- 人工修改：
  - `web/style.css` 增加 `[hidden] { display: none !important; }`，登录页/首页、登录/注册、红点三处同时生效；
  - `web/app.js` 预约成功后跳到“我的预约”，详情页显示当前预约状态与“前往我的预约”按钮，
    通知弹窗增加“我的预约”入口；
  - 服务端改为 4 个工作线程 + 请求队列，业务状态用互斥量串行化；写操作成功后立即落盘
    （`src/web/web_server.cpp`）。

## 记录 9：演示数据统一与数据“重置”排查（本轮）

- 场景：命令行用英文演示数据、网页用中文演示数据，两边共用 `data/` 时语言会打架；
  同时网页测试时数据看起来回到了初始状态。
- 排查结论：
  1. 早期版本只在进程正常退出时保存，强制结束会丢数据（已改为每次写操作即时落盘）；
  2. Windows 下 `SO_REUSEADDR` 允许两个实例同时绑定 8765，浏览器可能连到旧实例的另一个数据目录，
     表现就是“数据变成最初的样子”；
  3. 两个进程写同一数据目录会互相覆盖。
- 人工修改：
  - 新增 `include/campus/demo_seed.h`、`src/demo_seed.cpp`，命令行与网页共用同一份英文演示数据；
  - 新增 `include/campus/instance_lock.h`，同一数据目录只允许一个进程（进程号存活检查，异常退出后自动清理）；
  - `src/web/web_server.cpp` 改用 `SO_EXCLUSIVEADDRUSE` 独占端口，被占用时提示并换端口；
    启动时打印数据目录绝对路径并刷新输出；
  - `src/cli.cpp` 同样加单实例锁并打印绝对路径；
  - `build.bat`、`Makefile` 加入 `src/demo_seed.cpp`；`README.md` 补充演示数据与数据目录说明。
- 自测：新数据目录下 CLI/Web 均播种英文分类与商品；第二个实例被拒绝；端口冲突提示并改用 8766；
  创建商品后强杀再启动，数据仍在。

## 记录 11：同一浏览器多标签页登录不同账号（本轮）

- 场景：需要用同一个浏览器开多个标签页，分别以买家、卖家、管理员身份同时测试。
- 问题：原实现把 `sid` 放在 Cookie 里，同一浏览器所有标签页共享 Cookie，后登录的会覆盖前一个。
- 人工修改：
  - `src/web/web_server.cpp`：请求解析支持 `X-Session` 头，`CurrentUser()` 优先用该头（Cookie 仅作回退）；
    登录响应返回 `{"sid":..., "user":...}`，不再写 Cookie；退出只删除当前会话号。
  - `web/app.js`：登录后把 `sid` 存入 `sessionStorage`，所有请求带 `X-Session`；
    退出或收到 401 时清除本标签页会话。
- 自测：同一服务上同时保持买家、卖家、管理员三个会话；买家预约、卖家确认、管理员看统计互不干扰；
  买家退出后其会话失效，卖家会话仍有效。
