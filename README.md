# 校园二手交易系统（C++ 课程实现）

实验三：软件实现与构建。依据实验二的设计，用 C++17 实现一个校园二手交易系统，
同时提供图形界面（浏览器 Web UI）与命令行界面。

## 构建

依赖：MinGW-w64 g++ 14（或任意支持 C++17 的编译器）。

```bat
build.bat
```

生成三个程序：

| 程序 | 说明 |
|---|---|
| `build\campus_market_web.exe` | 图形界面：内置 HTTP 服务 + HTML 前端 |
| `build\campus_market.exe` | 命令行界面（无浏览器环境时可用） |
| `build\campus_tests.exe` | 单元测试（96 个断言） |

也可以使用 Make：`make`（依次构建三个目标）。

## 运行图形界面

```bat
build\campus_market_web.exe --data data
```

程序启动后不会自动打开浏览器，请手动访问 `http://127.0.0.1:8765/`；
如需启动时自动打开，加 `--open`。常用参数：`--port 8765`、`--web web`、`--open`。

首次运行且 `data/` 为空时自动写入 5 个中文分类、4 个账号和 4 件已发布商品。

## 界面

按实验二的设计稿实现 8 个页面：

1. 登录 / 注册（左品牌栏 + 右表单，登录、注册切换）
2. 商品检索（筛选侧栏：关键字、分类、价格区间、排序；卡片网格 + 分页）
3. 商品详情（图片占位、价格与状态、预约须知、预约 / 举报）
4. 发布商品（表单 + 发布规范，保存草稿或直接提交审核）
5. 卖家中心（指标卡、商品列表、待确认预约）
6. 商品审核（待审核列表 + 详情面板，通过 / 驳回并填理由）
7. 举报处理（举报列表 + 详情，判定成立下架 / 不成立）
8. 日志与统计（KPI、分类柱状图、近 7 天预约折线图、操作日志）

## 目录结构

```
include/campus/   领域模型、仓储接口、服务声明
src/              服务实现、文件仓储、命令行界面
src/web/          HTTP 服务与 JSON 接口
web/              前端页面（index.html / style.css / app.js）
tests/            单元测试
UML/              类图、分层架构图与行为图（PlantUML）
data/             运行时数据（自动生成，不纳入版本库）
```

## 与实验二设计的差异

实验二按 Web 应用设计（Vue + Spring Boot + MySQL）。实验三用 C++ 实现了同样的 Web 形态，
但技术栈更轻：

1. 前端由 Vue 改为原生 HTML/CSS/JS，页面结构与配色沿用实验二设计稿；
2. 后端由 Spring Boot 改为 C++17 内置 HTTP 服务（Winsock2），接口仍是 JSON；
3. 存储由 MySQL 改为 0x1f 分隔的文本表，仓储接口保持不变；
4. 去掉对象存储与 Redis，图片位置以占位块表示；
5. 并发控制由数据库唯一索引改为服务内互斥量 + 仓储二次校验，语义一致。

## 关键实现

- 商品状态机集中在 `CanTransition()`，非法转换抛 `DomainError(kStateError)`；
- 预约支持幂等号：同一请求重发返回首次结果；
- 同一商品最多一条有效预约，见 `ReservationService::Reserve`；
- 密码加盐迭代哈希，连续 5 次失败锁定 15 分钟；
- 举报 24 小时内去重，判定成立时下架商品并作废有效预约；
- 操作日志只追加，统计口径排除已取消预约；
- HTTP 层只做协议与鉴权，业务规则全部在服务层，命令行与 Web 共用同一套服务。

## 部署与并发说明

- 服务为单进程、4 个工作线程；请求可并发进入，业务状态由互斥量串行化，保证数据一致。
- 会话按 Cookie 区分，不同浏览器可同时以不同账号登录，数据实时共享。
- 每次写操作（POST）成功后立即写入 `data/` 下的文本表，进程被强制结束也不会丢已提交数据。
- 默认只监听 `127.0.0.1`，没有 HTTPS、限流与 CSRF 防护，仅适合本机或内网演示；
  如需公网访问，请在前面加反向代理（HTTPS）、限制来源，并评估数据与账号安全。

## 命令行语言

命令行的菜单、提示、状态与错误信息均为英文；演示数据与用户数据可以是中文，
程序会在 Windows 控制台切到 UTF-8（输入与输出都设置代码页），中文标题、分类和描述可正常显示。
Web 版界面保持中文。

## 演示数据与数据目录

- 命令行与网页共用同一份中文演示数据，由 `src/demo_seed.cpp` 统一播种，
  两边看到的数据完全一致。
- 服务启动时会打印**数据目录的绝对路径**；同一数据目录加了单实例锁，重复启动会直接提示并退出，
  避免两个进程互相覆盖数据。
- 端口被占用时会提示，并自动改用下一个端口（8766、8767…），不会出现两个实例同时绑定 8765。
- 网页服务默认不自动打开浏览器，需要时加 `--open`。

## 多账号同时测试

登录会话按**标签页**隔离：登录成功后会话号存在当前标签页的 `sessionStorage`，
之后每个请求带 `X-Session` 头，服务端按会话号识别用户。

- 同一浏览器直接开多个标签页（或 Ctrl+N 新窗口），每个标签页分别登录不同账号即可同时操作；
- 刷新页面会保持当前标签页的登录；关闭标签页该会话结束；
- 在一个标签页点“退出”只影响该标签页，其他标签页的登录不受影响；
- 如果页面是改动前打开的，先 Ctrl+F5 强刷一次再登录。

## 商品图片与刷新

- 发布商品时可选择一张图片；前端会把图片压缩到 900px 内再上传，后端保存到 `data/uploads/`，
  页面通过 `/uploads/<文件名>` 访问，商品列表、详情、审核和卖家中心都会显示缩略图。
- 商品检索、我的预约、卖家中心、商品审核、举报处理、统计报表页面都带“刷新”按钮。
- 页面导航只在顶部工具栏，卖家/管理员页面不再重复显示侧边栏。
- 页面启动时会对比 `/api/version`，发现版本不一致会提示按 Ctrl+F5 刷新，避免旧页面出现异常。

## 管理员下架与列表细节

- 管理员在商品详情页看到的是“下架并退回草稿”，不是“举报”；下架需填写理由，
  效果与审核驳回一致：商品退回草稿、记录理由、作废有效预约并通知卖家。
- 管理员浏览商品详情不计入浏览次数（买家、访客正常计数）。
- 图片按比例缩放显示（不裁剪）；上传按钮与清除按钮统一尺寸对齐。
- 筛选无结果时只在右上角提示，商品区域保持空白。
- 列表表格固定列宽；“我的预约”“我的商品”“待审核”“操作日志”等列宽不再随内容跳动。
- 从卖家中心、审核、举报等页面进入详情后，点“返回”回到来源页面，而不是首页。
